# Customizing Conductor

Conductor is designed to be portable. The safest pattern is to keep the public skill files mostly stable and put leader-specific context in a local Conductor Profile.

## Recommended Local Files

Create a `local/` folder for private, uncommitted material:

```text
local/conductor-profile.md
local/leader-review-profile.md
local/voice-profile.md
local/advisor-board-profile.md
local/source-map.md
local/examples/
```

The repo ignores `local/` by default. Use it for anything that names real people, clients, board members, staff members, donors, students, customers, or internal projects.

## What To Customize First

Start with `docs/onboarding.md` and create a Conductor Profile. Use `docs/sample-conductor-profile.md` to calibrate specificity, then customize only what the installed skills need:

- Role, organization, and strategic arc.
- Stakeholders and sensitive audiences.
- Source Map and off-limits sources.
- Cadence Contract.
- Communication duties and voice notes.
- Preferred directness and off-limits behavior.

This is usually enough. Do not edit all twelve skill files just to personalize one leader.

## When To Edit Skill Files

Edit a skill file when the change should be true for every run of that skill. Good reasons include:

- Your institution uses a different recurring source stack.
- You want different output section names.
- You are adapting the bundle for a specific sector.
- You are maintaining a private fork for one organization.
- You want to remove public branding from an internal-only copy.

Avoid editing a skill file to add private examples, private names, or temporary context. Put those in `local/` and paste them into the installed project or GPT.

## Branding And Attribution

For internal use, you can rename Conductor, change local examples, and adapt sector language.

For public redistribution, keep attribution to MehtaCognition and preserve adapted-framework notes, especially where the skill cites an outside source or methodology. If you publish a modified version, make it clear what you changed.

The Coaching Diagnostic carries the strongest MehtaCognition methodology. You can adapt sector examples, but do not remove the diagnostic discipline: reframing over prescription, questions over checklists, and structural pattern over surface symptom.

## Profile Storage Convention

Use one canonical profile and copy it into each installed skill environment:

```text
local/conductor-profile.md          # base profile
local/leader-review-profile.md      # generated by Exec Review
local/voice-profile.md              # generated by Leader-Pen or refined through Leader-Edit
local/advisor-board-profile.md      # generated by Personal Board of Advisors
```

When Exec Review generates a Leader Review Profile, either paste that block into `local/conductor-profile.md` under a `Leader Review Profile` heading or keep it as `local/leader-review-profile.md` and paste both profiles into installed skills.

When Leader-Pen builds a voice profile, keep it in `local/voice-profile.md` and paste it into Leader-Pen and Leader-Edit.

When Personal Board of Advisors builds an Advisor Board Profile, keep it in `local/advisor-board-profile.md` or paste it into `local/conductor-profile.md` under an `Advisor Board Profile` heading. Keep real advisor names, source notes, and private rationale in `local/`, not in public skill files.

## Updating From The Public Repo

Conductor will improve over time as leaders use the skills and send feedback. Check `CHANGELOG.md` before updating installed skills, and keep custom material separate so updates are easy.

If you cloned the repo:

```bash
git pull
python3 .claude/checks/bundle-integrity.py --explain
```

If you forked it:

```bash
git remote add upstream https://github.com/mehtacognition/mc-conductor.git
git fetch upstream
git merge upstream/main
python3 .claude/checks/bundle-integrity.py --explain
```

If you downloaded a ZIP, download the latest ZIP and compare public files against your installed copies. Your `local/` files should not need to change unless the update adds a profile field you want to adopt.

## Updating Installed Skills

Repo updates do not automatically update Claude Projects, custom GPTs, or pasted prompts.

When a public skill changes:

1. Open the updated `skills/<n>-<name>/SKILL.md`.
2. Keep your current Conductor Profile in `local/`.
3. Replace the old installed skill instructions with the new skill file.
4. Paste the latest Conductor Profile above the skill instructions.
5. Run one test session with a familiar input.

If you made private edits directly inside a skill file, compare your edited copy to the new public copy and reapply only the edits that still matter.

## Sending Feedback Upstream

See `CONTRIBUTING.md` before opening an issue or pull request. Useful feedback includes:

- Which skill you used.
- What leadership context it served.
- What source material you brought.
- What output was useful or off.
- What prompt language you changed.
- An anonymized before/after excerpt if safe to share.

Do not send private names, board materials, personnel details, student/customer data, financials, or confidential strategy. Anonymize aggressively.

Feedback can become future repo updates, but private leader context should stay private.
